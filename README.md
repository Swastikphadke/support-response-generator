# Support Response Generator

[![Built with askThili](https://ask.thili.ai/api/v1/public/projects/35rtapa94n/badge.svg)](https://ask.thili.ai/b/35rtapa94n)

This CLI tool, designed for retail customer support agents, leverages a next-word predictor to streamline response drafting. By analyzing a corpus of past support interactions, it offers intelligent suggestions, helping agents quickly and consistently address common customer queries.

## What you are building

**Goal.** You will build a command-line interface (CLI) tool that helps customer support agents draft responses by generating next-word suggestions based on past support interactions.

**Done when.** The tool successfully loads an anonymized corpus, implements an n-gram model with smoothing, generates coherent next-word suggestions for agent input, and provides a functional command-line interface for agents to use.

## Milestones

Tick these off as you go, and commit after each one.

- [ ] **1. Prepare an anonymized corpus of customer support interactions.**  
      Hint: For preparing the corpus, focus on text cleaning, tokenization, and anonymization techniques.
- [ ] **2. Implement the n-gram model with smoothing.**  
      Hint: Implement the n-gram model and apply smoothing techniques as learned in the `lfllm-lfnextword` drill.
- [ ] **3. Create a text generation function to suggest response continuations.**  
      Hint: Develop a function that uses your n-gram model to predict and suggest the most probable next words or phrases.
- [ ] **4. Build a command-line interface for agents to get suggestions.**  
      Hint: Design a user-friendly command-line interface to take agent input and display the generated suggestions.

## Run it

You need Python 3.12 and git.

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then choose a model; see the comments inside
python -m app.cli hello
pytest
```

Your work goes in `app/core.py` (one stub per milestone) and `tests/test_core.py`. The first tests pass already; they
check the plumbing.

## Settings and secrets

Model settings live in `.env`, which is ignored by git. **Never commit `.env` or paste a key into code.** If a key ever
reaches GitHub, treat it as leaked and make a new one.
